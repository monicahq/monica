# Research: Contact list columns

| # | Decision | Rationale | Rejected |
| --- | --- | --- | --- |
| R1 | One `contact_list_columns` table, one row per column per vault. No row for Name. No rows at all means the defaults. | A vault's list is several ordered columns, and each needs a source, a heading, a position and a visibility. | A JSON column on `vaults`: not queryable, and its shape would be validated only in PHP. |
| R2 | Save replaces the vault's whole set in one transaction. Reset to defaults is client side: the screen is given the default set and restores it into the form. | The screen edits a list and applies it once. Replacing it is one statement and needs no diffing. | A write per change, like `x-position-form`: that contradicts FR-008, which applies nothing until Save. |
| R3 | A template field column stores `section_id` and `field_key`. | Fields belong to section versions, sections are shared across templates, and a new version copies its fields with new ids but the same key. Only the section and key survive both. | `field_id`: breaks at the next version. Template plus key: the same section in two templates would become two columns. |
| R4 | The shared sources are an enum, `ContactListColumnSourceEnum`: `nickname`, `email`, `phone`, `birthday`, `template`, `last-spoke`, `added`, `field`. It is cast. | These are defined by the product and are never withdrawn without a migration, unlike the 041 values that are read with a fallback. | Free strings. |
| R5 | Email and phone gather values by field type. Birthday gathers the `birthday` key from any section, the way `OwnedFields` does. The add menu leaves out email and phone fields and the `birthday` key, since the shared columns already cover them. | One word for one meaning: two Email columns that differ invisibly is the confusion FR-012 exists to prevent. | Offering both. |
| R6 | The add menu offers fields from the published version of every active contact template. It leaves out `divider`, `heading`, `help`, the repeater itself, `file`, `image`, `avatar` and every `is_sensitive` field. | Those hold no value, or a value that cannot be shown as a line of text, or one the list cannot mask. | Walking every version any contact is on: slower, and it offers fields no new contact can get. |
| R7 | A field carried by every active template is listed under "Shared by all templates". Otherwise it is listed under "Unique to some templates", with the templates that carry it as badges. Its label is the field's label, and the section's name is shown when two offered fields share a label. | This matches the design's two groups, derived from the data rather than from a fixed list. | Always prefixing the section: noisy when labels are distinct. |
| R8 | Cells are read by `ContactListCells`, a small object beside `ContactsViewModel`. It makes one query for the field ids behind the configured columns and one for the page's values (`is_detached = false`, ordered by field position then row position), then formats them with `FieldValueFormatter`. | Two queries per page whatever the column count, and the formatter already renders every type for the reader. | A query per column. |
| R9 | A column whose section is deleted, or which no active template's published version carries any more, is kept. The customise screen marks it "No template supplies this any more", and the list skips it. | Principle VIII. Removing it is the person's choice (FR-015). | Deleting the row. |
| R10 | Everybody orders by `is_favourite` first, then by the chosen sort. The group heading is decided the way letter headings were carried across pages: a page opening mid-group repeats no heading. Letter headings and the sort selects are removed. | FR-004. The headings now carry the sort. | Two separate queries: breaks `simplePaginate`. |
| R11 | Headings are links to the same address with `sort` and `direction` set, with `x-target.push="contacts"`. `aria-sort` sits on the `th`. Only the headings in FR-006 are links. | 041 already records whatever address is rendered, so no new write is needed. | Buttons posting a form. |
| R12 | The list is a real `<table>`. The name cell holds the link, stretched over the row. The "+N" control is a button above that stretch, with `aria-expanded`. | Native table semantics for screen readers. A row cannot be an `<a>` inside a `<table>`. | ARIA `role="table"` on divs, as the design has. |
| R13 | The customise screen is one Alpine component, `resources/js/contact-list-columns.js`. It finds its root from the element acted on (components.md). It posts `columns[n][...]` in DOM order. The grip moves a row on ArrowUp and ArrowDown, and a polite live region says "Moved to position 3 of 5". | This follows `life-event-type-fields.js`, the one other editor that reorders before saving. | Extending `x-sortable-row`, which saves on every drop. |
| R14 | The add menu is `x-actions-menu`, with each item a `<button>` carrying the field label and its template badges. | It is the component holding the menu contract (components.md). | A hand-rolled popover. |
| R15 | Routes are `GET vaults/{vault}/contact-list-columns/edit` and `PUT vaults/{vault}/contact-list-columns`. | Anything under `contacts/{x}` collides with a contact slug (`ReservedAddressWords`). | Reserving `columns` as a contact slug. |
| R16 | The API adds `GET` and `PUT vaults/{vault}/contact-list-columns`. A template field is named there by section uuid and key. The API contact list gains a `columns` array per contact, holding the visible columns' values. | Principle X and FR-016. The uuid is the section's API identity. | Leaving the list values out of the API. |
| R17 | Copy is in British English ("Customise contact list"). Default headings are stored as null and translated on display. A renamed heading is stored as typed. | The existing copy uses British spelling (`organise`, `Favourite`). FR-014. | Storing the translated default, which would freeze it in one language. |
| R18 | No new CSS. The design's `mn-*` tokens (`page`, `canvas`, `card`, `ink`, `body`, `muted`, `hairline`, `hover`) already exist as Tailwind colours in `app.css`. | Memory: Tailwind, not custom CSS. | Importing the design system's stylesheets. |
