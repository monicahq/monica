# Implementation Plan: Vault card values in the API

**Branch**: `2026-11-27-vault-card-api` | **Date**: 2026-11-27 | **Spec**: [spec.md](spec.md)

## Summary

The vault resource gains `last_visited_at`, `faces` and `upcoming_reminder_count`, the list gains
`sort=recent`, and a token-readable avatar address serves the thumbnail. The rules move onto `Vault`
and `ReminderOccurrence` so the web card and the API read one source ([research](research.md) R1).

## Technical Context

**Language/Version**: PHP 8.5, Laravel 13

**Primary Dependencies**: Sanctum (tokens), Laravel MCP

**Storage**: SQLite, MySQL, PostgreSQL; no schema change

**Testing**: PHPUnit, `composer test:parallel`

**Target Platform**: the JSON API, read by the Android app

**Project Type**: web application with a JSON API

**Performance Goals**: a page of 100 vaults in a constant number of queries (R2, R3, R8)

**Constraints**: no driver-specific SQL; no ORDER BY in the count subquery (R3)

**Scale/Scope**: up to 100 vaults per page, four faces each
