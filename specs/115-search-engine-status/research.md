# Research: Search engine status

| # | Decision | Rationale | Rejected |
| --- | --- | --- | --- |
| R1 | The check is an action, `CheckSearchEngine`, called by the controller on every GET. "Check again" is a link to the same screen. | `CheckTelegramWebhook` is the precedent for questioning an outside service and changing nothing. A reload is the simplest live read (FR-011). | A cached status with a refresh POST: a stale answer is the failure this screen exists to remove. |
| R2 | One action, a `match` on `config('scout.driver')`, one private method per engine, returning an array shape. | Four engines, each a few lines. `CheckTelegramWebhook` returns an array shape too. | An interface with one class per engine, or a value object: more files than logic. |
| R3 | The engines are questioned with Laravel's HTTP client, `timeout(2)` and `connectTimeout(1)`, never through Scout's client. Health is asked first and a failure stops there. The remaining calls go in one `Http::pool()`. Worst case: 2 + 2 seconds. | Scout builds the Meilisearch client with no timeout, and the Typesense settings (2 seconds, 3 retries, 1 second apart) can take 9 seconds, both over FR-005. `Http::fake()` tests every engine. | Scout's `__call` to the engine client: no control of the time. |
| R4 | What each engine is asked is in [contracts/http.md](contracts/http.md). Meilisearch gives everything in `/stats`. Typesense reports no size per collection. Algolia has no health or version endpoint: listing the indexes succeeding is its health. | One or three calls per engine, no call per record. | Typesense `/metrics.json`: the size of the whole node, which would read as the size of one index. |
| R5 | The database engine is questioned in the database. Documents indexed is the number of rows whose `search_name` is not null, because `MaterializedDatabaseEngine` writes the document to the `search_*` columns and sets them to null on removal. Health is healthy, size is not reported, and the screen says the engine does not tolerate typing mistakes. | The same drift exists there: a record never sent to search has null columns and is not found. | Reporting the database engine as always complete. |
| R6 | Records held is `Model::query()->count()` for `Contact`, `Entity` and `LifeEvent`. The index name is `(new Model)->searchableAs()`, which carries the prefix. | No model defines `shouldBeSearchable()`, and `scout.soft_delete` is false, so the default scope counts exactly what is sent. The list of three models is the one in `config/scout.php`. | Discovering searchable models by reflection. |
| R7 | Before any call, the action resolves the engine through Scout's `EngineManager` inside a `try`. An exception is reported as unreachable with its message. The tests of the outside engines replace `EngineManager` in the container with a stub, since the Algolia client is not installed and Scout would throw. | Scout throws there when the configured engine's client is missing, which is the spec's edge case, and search itself is broken in that state. The stub also lets the missing client case be tested. | Ignoring it: the screen would say healthy while search fails. |
| R8 | Any other driver (`collection`, `null`, `turbopuffer`) returns "no status available" with the records held and no index figures. | Spec assumption. Turbopuffer has no model configured in `config/scout.php`. | Supporting them: nothing in the instance uses them. |
| R9 | The failure reason shown is the HTTP status, or the connection error's message with the key and secret replaced if they appear in it. The address shown is the host only. The key is sent in a header, never in the URL. | FR-009. A test asserts the key is in none of the action's output for each engine. | Showing the raw response body: an engine may echo the request. |
| R10 | Sizes go through `App\Helpers\StorageSize`. The difference is worded with `trans_choice()` (":count missing", ":count left over"), and equal counts read "Complete". | Existing helper. The counted phrase rule of `code-style.md`. | Formatting bytes in Blade. |
| R11 | No flag and no policy. Opening the screen writes nothing to the administrator log. | It ships finished, the `administrator` middleware is the only rule, and reading is not an action on anybody (FR-012). | `LogAdministratorAction` on each view: noise in the record. |
| R12 | The rebuild is a queued job, `RebuildSearchIndex`, started by the action `StartSearchIndexRebuild`. The job runs `scout:sync-index-settings` when the engine has settings, then `Model::removeAllFromSearch()`, then `Model::sendToSearch(Model::query())`, the order `monica:rebuild-search-index` uses, so an index created on the way can still be filtered. | Walking every record of one kind does not belong in a web request. Both calls already exist: Scout's flush and the trait's chunked, queued sync. | Emptying in the request and queueing only the sync: an engine that fails to empty would answer the administrator with an error page. |
| R13 | The job is `ShouldBeUnique`, keyed by the model class, on the `low` queue. A second press while one is waiting or running starts nothing, and the screen still says the rebuild has started. | Two rebuilds of one index interleave an empty and a refill. `DetectDuplicateContacts` is the precedent. | A lock row with a progress state: a table for a button. |
| R14 | `StartSearchIndexRebuild` takes the kind (`contacts`, `entities`, `life-events`) and the administrator, refuses any other kind with `ModelNotFoundException`, and logs `AdministratorActionEnum::SearchIndexRebuildStarted` with the real index name (`searchableAs()`). | The shape of `ActivateFlagForEveryAccount`. FR-014. | Logging from the job: the job does not know who asked. |
| R15 | The same rebuild serves the database engine: its `flush()` sets the `search_*` columns to null and the sync writes them again. | No branch per engine. Scout's Typesense flush deletes the collection and the sync creates it again, Meilisearch and Algolia keep their settings. | A separate path for the database engine. |
| R16 | The route is `POST admin/search/{kind}/rebuild` inside the `password.confirm` group. The view uses `x-modal.warning` with `confirms-password` and one `x-modal.confirm-password`, as the Flags screen does. The button is rendered only when health is healthy (FR-015). | FR-016 and the existing pattern for an instance wide change. | A second sentence under the button instead of a modal: `CLAUDE.md` asks for a warning before a destructive action. |
| R17 | Counting is not bounded. A large instance pays three or six `count()` queries per page load. | An admin screen opened by hand. The spec's edge case stays open and the pull request says so. | A query timeout with "not counted": more states than the problem has shown. |

## Not confirmed

The response fields of R4 come from the engines' public documentation, not from a live engine.
The plan's last step checks Meilisearch and Typesense by hand. Algolia cannot be checked without an
account, so its method is covered by `Http::fake()` only. That `password.confirm` returns to the
screen after a POST is assumed from the Flags screen, not traced.
