# Research: MCP coverage and stricter section values

| # | Decision | Rationale | Rejected |
| --- | --- | --- | --- |
| R1 | `FieldValueRules::for()` emits `fields => ['nullable', 'array:<top level input ids>']`, `fields.{id}.* => ['array:id,values,labels,label_wordings,unknown_year']` and `fields.{id}.*.values => ['nullable', 'array:<child input ids>']`. | All seven callers build their rules there: four merge them after their own `fields => ['array']`, so the later key wins (`SaveFieldValuesRequest`, the API section controller, both entity controllers), and three validate them alone (`SaveLifeEventRequest`, both life event API controllers). The ids are those of fields without a parent, since `inputFields()` may hand children too. `array:` with keys refuses any other key and names it. | A rule per controller: six copies. |
| R2 | A row without `values` stays allowed (spec amended). | An HTML form cannot send an empty list: a blank row, or a row whose only children are a radio or a multiselect left empty, reaches the server with no `values` key. `SetFieldValues` already reads that as a row with nothing filled in. The reported mistake (child ids beside `values`) is caught by R1's key list. | Requiring `values`: breaks the interface. Filling `values` in three web form requests: code to defend a rule that protects nothing. |
| R3 | `unknown_year` is accepted in a row and honoured: `SetFieldValues` reads the row's `unknown_year[<child id>]` when it writes that child, where it reads the top level `yearIsUnknown` today (FR-013). | `x-field-repetitions` sends it for a date child, and nothing in `app/` reads it, so the box is ignored. The value writer already takes `yearIsUnknown`; only the row's answer has to reach it. | Refusing the key: breaks the interface. A separate spec: same defect class as the feedback, a few lines. |
| R4 | A section with no input field emits `array:` with an empty list, which refuses every key. | Laravel compares keys against `['']`. Nothing can legitimately be sent. | Special case. |
| R5 | The error names the field by its label through the existing attribute names; a row is named by its index in the key Laravel reports (`fields.12.0`). | `SaveFieldValuesRequest::attributes()` and the API controllers already map `fields.{id}`; the row index is in the message key. | A custom message per rule. |
| R6 | Value list API: eight routes nested as `value-lists/{valueList}` and `value-lists/{valueList}/items/{valueListItem}`, addressed by integer id, reaching only shared lists (`is_shared`), see [contracts/api.md](contracts/api.md). | The existing `GET value-lists` addresses by id and shows shared lists only; `ValueList` has no uuid. Nesting items under their list gives the MCP lookup its parent, as knowledge list items do. The web routes are flat because the screen is one page. | A uuid column: a migration for no reader. Flat API routes: an item lookup without its list. |
| R7 | Controllers follow `LifeEventCategory*Controller`: `ValueListController`, `ValueListItemController`, `ValueListItemActivationController`, `ValueListItemPositionController`. Policy refusals become 422 on the record's key. | Existing API pattern for the same four verbs. | |
| R8 | `ValueListResource` and `ValueListItemResource` replace the inline arrays of `ValueListController::index`. The item gains `is_active` and `position`, which is additive. | Four endpoints now return a list or an item; one shape. The index already returns inactive items without saying so. | Keeping inline arrays: four copies. |
| R9 | The four item and list refusals are the policies' wordings (`This list stays.`, `The value is in use and stays.`, `This value list does not take choices of its own.`), as `policies.md` asks. | Already shared with the screen. | |
| R10 | MCP: eleven tools, one per endpoint, mirroring through `answerThroughApi()`. Two lookups join the trait: `valueList(Request, string)` and `valueListItem(ValueList, string)`. Delete tools return their own sentence, as `DeleteGroup` does. | `.claude/rules/mcp.md`. | |
| R11 | `App\Helpers\Duration` holds `LONGEST_IN_MINUTES = 525600` and `wording(int $minutes): string`, which joins the non-zero parts in weeks, days, hours and minutes, each through `trans_choice()` (`:count week|:count weeks`, and so on), separated by a space. | Five sites print a duration (`FieldValueFormatter`, `LifeEventDetailsViewModel`, `ContactTimelineBlock`, `ContactMarkdownViewModel`, and the contact list through the formatter); four sites hold the cap (`FieldValueRules`, `SaveLifeEventRequest`, the two life event API controllers). One constant, one wording. Months and years are not fixed lengths, so they are left out. | Months: 3 months is not a whole number of minutes. A per-locale list separator: a space reads correctly in every shipped locale. |
| R12 | The duration inputs gain `max` from the constant. | The browser then refuses before the server does. | |
| R13 | The Duration description in `FieldCatalogueViewModel` gains one sentence pointing at reminders for something that comes back. | FR-012. | A help bubble: the catalogue entry is where the type is chosen. |
| R14 | No migration and no data change. | Stored minutes are unchanged; only the cap and the reading change. | |
